M365 Cloud Migration &
Infrastructure Modernization

Replaced legacy Active Directory, Exchange Server, WSUS patching and mapped file shares with Microsoft 365 cloud services, moving identity, mail, devices and files in planned phases with no lost data.

My role
Planned and executed the migration end to end
Scope
Identity, mail, devices, files, hardware
Approach
Assess → Plan → Migrate → Validate → Optimize

UIWhat it looks like

The problem

  • Identity lived in on-prem Active Directory with no MFA or SSO
  • Exchange Server was ageing and costly to maintain
  • Patching depended on WSUS and manual effort
  • Files sat in mapped shared folders with weak sharing and no versioning
  • Old hardware drove a steady stream of support tickets

What I built

  • Entra ID as the cloud identity with MFA and SSO
  • Mailboxes moved to Exchange Online in batches
  • Devices enrolled in Intune with update rings replacing WSUS
  • Shared folders restructured into SharePoint document libraries
  • Hardware refreshed to small-form-factor PCs, enrolled on day one

FlowEnd-to-end process

  1. 1

    Assess

    Inventoried users, mailboxes, shares, devices and apps. Flagged stale accounts and oversized shares before anything moved.

    PowerShellAD reportsGet-ADUser · Get-Mailbox · share size reports
  2. 2

    Plan

    Designed the target tenant: naming, licensing, security groups, SharePoint site structure and a cutover calendar per team.

    Entra IDSharePoint
  3. 3

    Sync identities

    Synced and matched on-prem accounts into Entra ID so users kept one sign-in, then enabled MFA registration.

    Entra IDMFA
  4. 4

    Migrate mail

    Moved mailboxes in batches out of hours, then switched MX/Autodiscover DNS once the last batch completed.

    Exchange OnlineDNSExchange migration batches
  5. 5

    Migrate files

    Copied shared folders into SharePoint libraries with permissions mapped to security groups.

    SharePointOneDriveSharePoint Migration Tool
  6. 6

    Move devices

    Enrolled refreshed PCs in Intune, replacing WSUS with Windows Update rings and compliance policies.

    IntuneAutopilot
  7. 7

    Validate & optimize

    Tested mail flow, file access and sign-ins with each team, then retired the old servers.

    TestingRunbooks

Microsoft Entra Conditional Access
& MFA Architecture

Designed a group-based Conditional Access model in Entra ID so every new user is protected the moment they are provisioned: MFA for all, stronger MFA for admins, legacy protocols blocked and access shaped by location and device.

My role
Designed, piloted and rolled out the policy set
Model
Group-based, applied automatically at provisioning
Rollout
Report-only → pilot group → everyone

UIWhat it looks like

The problem

  • No consistent identity security model across users
  • Legacy authentication (IMAP/POP/SMTP basic auth) still open
  • No location-based or device-platform restrictions
  • Admin accounts used the same MFA as everyone else

What I built

  • A small set of named, group-targeted CA policies
  • MFA required for all standard users
  • Phishing-resistant MFA required for admin roles
  • Legacy authentication blocked tenant-wide
  • Named locations for trusted offices, with a VPN path for remote laptops
  • Break-glass accounts excluded and monitored

FlowEnd-to-end process

  1. 1

    Baseline sign-ins

    Reviewed sign-in logs to see who used legacy auth, which locations and which device platforms were in use.

    Entra sign-in logsGET /auditLogs/signIns
  2. 2

    Define named locations

    Created trusted office IP ranges and country rules used by the location policies.

    Named locationsPOST /identity/conditionalAccess/namedLocations
  3. 3

    Build policies in report-only

    Created each policy in report-only mode to measure impact without blocking anyone.

    Conditional AccessPOST /identity/conditionalAccess/policies
  4. 4

    Pilot with a group

    Switched policies on for an IT pilot group, fixed edge cases (shared mailboxes, service accounts).

    Security groups
  5. 5

    Tie to provisioning

    New users land in the right security groups automatically, so policies apply from their first sign-in.

    Power AutomateEntra IDPOST /groups/{id}/members/$ref
  6. 6

    Enforce & monitor

    Turned policies on for everyone and reviewed sign-in failures and CA insights weekly.

    WorkbooksSign-in logs

Platforms

Auth

UIWhat it looks like

The problem

  • Every new hire had to be created by hand in 5+ separate tools
  • Access was inconsistent between platforms
  • Leavers were sometimes missed in one system
  • Asset and device records drifted out of sync

What I built

  • Entra ID set up as the identity provider for each app (SAML SSO)

    Asset inventory
